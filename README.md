# In Progress

Локальный прототип на HTML, CSS и обычном JavaScript. На главной — полка с обложками. Каждая обложка ведёт к подборке с собственным адресом. Все изображения лежат в проекте. Обложки и работы сгенерированы для демонстрации, подписи к ним — примеры редакционных заметок.

## Открыть готовый проект

1. Распакуй архив `in-progress.zip` в удобное место, например в «Документы». Внутри уже есть папка `in-progress`.
2. Запусти Visual Studio Code. Выбери **File → Open Folder…** и открой папку, в которой рядом лежат `index.html` и `style.css`.
3. В панели Explorer слева появятся файлы проекта. Устанавливать пакеты через терминал не требуется.

## Как разложены файлы

```text
in-progress/
├── index.html       Главная страница с полкой
├── category.html    Шаблон отдельной страницы раздела
├── style.css        Шрифты, композиция, анимация и мобильный вид
├── data.js          Названия категорий, картинки и тексты работ
├── script.js        Ссылки на полке, прокрутка и заполнение галереи
├── assets/
│   ├── covers/      Шесть квадратных обложек в JPG
│   └── gallery/     Изображения публикаций в JPG
└── README.md        Этот гайд
```

Если собираешь проект вручную, открой **File → Open Folder…**, создай папку `in-progress` и открой её. В Explorer нажимай **New File** для каждого из пяти файлов с кодом. Открой одноимённый файл из комплекта, скопируй его содержимое целиком, вставь в созданный файл и нажми **Ctrl+S**. Перетащи папку `assets` из комплекта в корень проекта. Проверь, что `index.html` и `assets` находятся на одном уровне.

## Запуск через Live Server

1. В VS Code нажми **Ctrl+Shift+X**. Введи в поиск `@id:ritwickdey.LiveServer`. Установи **Live Server** от **Ritwick Dey**. [Страница расширения](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer)
2. В Explorer нажми правой кнопкой на **index.html** и выбери **Open with Live Server**. Браузер откроет главную на локальном адресе. Используй адрес, который выбрало расширение.
3. Поставь окна редактора и браузера рядом. Измени фразу `A home for unfinished ideas.` в файле `index.html` и нажми **Ctrl+S**. В браузере появится новый текст.
4. Открой **Photo**. После перехода в адресе появится `category.html?id=photo`. Измени название работы в `data.js` и сохрани файл — Live Server перезагрузит страницу категории.
5. Для остановки нажми **Ctrl+Shift+P** и выполни **Live Server: Stop Live Server**.

Для быстрого просмотра можно открыть `index.html` двойным щелчком в Проводнике. При таком запуске после правок обновляй страницу вручную.

## Что менять первым

- **Название на главной и подзаголовок** находятся в `index.html`. Название в шапке разделов — в `category.html`.
- **Цвет фона** задаёт `--paper` в начале `style.css`. Переменная `--display` задаёт Sitka для заголовков и Georgia для устройств без Sitka.
- **Подъём обложки** задают правила `.sleeve:hover` и `.sleeve:focus-visible`. Меняй величину `translateY`, чтобы увеличить или уменьшить подъём.
- **Полка** показывает обложки в порядке массива `collections` в `data.js`. Под ней находится полная галерея All Ideas. Кнопка All ideas в навигации открывает её на отдельной странице.
- **Заголовок и заметка к работе** хранятся в `posts` в полях `title` и `note`. В `alt` опиши изображение для пользователей экранного диктора.

## Добавить свою работу

1. Положи квадратное JPG-изображение в `assets/gallery/`, например `window-light.jpg`.
2. Найди в `data.js` нужную категорию. В её массиве `posts` скопируй одну запись. Между записями поставь запятую.
3. В новой записи укажи `image: "window-light"`, затем заполни `title`, `alt` и `note`. Расширение `.jpg` добавляет скрипт.
4. Сохрани файл и открой раздел. Если изображение не появилось, сравни имя в `image` с именем файла, включая регистр.

## Добавить категорию

Скопируй целый объект категории внутри `collections`, разделив объекты запятой. Задай уникальный короткий `id` латиницей, например `collage`, название `name`, описание `about` и свои работы в `posts`. Обложку положи в `assets/covers/collage.jpg`. Новый раздел получит адрес `category.html?id=collage`. При нехватке места на полке появятся кнопки прокрутки. На телефоне полка листается пальцем.

Начальные три раздела — AI Generated, Photo и Site Inspirations. Разделы Design Sketches, Experiments и Notes добавлены как примеры из макета. Для полки из трёх разделов убери эти три объекта из `collections`.

## Как устроен прототип

Оба HTML-файла подключают `data.js` перед `script.js` с атрибутом `defer`. Сначала браузер читает разметку и получает список категорий, затем запускает код страницы. Главная создаёт обычные ссылки. На странице раздела скрипт читает параметр `id` из адреса и заполняет HTML-шаблон работы для каждой записи в `posts`. Поэтому раздел можно открыть напрямую, обновить или открыть в новой вкладке.

**All Ideas** поддерживает поиск по названию, описанию и тегам, выбор категории и сортировку по дате. На узком экране фильтры раскрываются через **Collections**. Под изображением видны название и автор. Кнопка **•••** раскрывает категорию и указанный автором статус. Значок закладки сохраняет выбор в localStorage этого браузера.

Через **Upload idea** можно выбрать или перетащить несколько изображений. Первое служит обложкой. В **Photo settings** у каждого снимка можно задать длину большей стороны в пикселях и выбрать JPEG, WebP или PNG. Для JPEG и WebP доступны уровни качества 65%, 85% и 95%. Предпросмотр показывает итоговые параметры и вес файла. При экспорте браузер сохраняет отдельную копию, а ссылка **Open original** открывает исходный файл. Описание и автор находятся в **Notes & credit**, теги и статус — в **Publishing options**.

Для проверки открой проект через Live Server, опубликуй работу, обнови раздел и найди её в All ideas. Изображения и подписи хранятся в IndexedDB текущего профиля браузера и адреса сайта. Для Live Server используй один и тот же адрес и порт. У GitHub Pages своё локальное хранилище.

## Версии и продолжения

Открой папку проекта в VS Code и запусти Live Server для `index.html`. Для быстрой проверки открой **All ideas → Last light on the ridge → Continue This Idea**. Добавь изображение, укажи название и опубликуй своё продолжение. **Explore Evolution** покажет связь с версией оригинала.

На своей публикации выбери **Add version**, загрузи изображение и при желании оставь заметку. Переключай версии кнопками под фото. Щелчок по снимку открывает его в полном размере. Разрешение **Allow others to continue this idea** находится в **Publishing options** при загрузке и в **More details** после публикации.

Логика истории и дерева находится в `evolution.js`. IndexedDB хранит идентификатор этого браузера, файлы и связи. Существующие загрузки становятся версией 01 и сохраняют авторство. Для проверки после перезапуска используй тот же профиль, адрес и порт Live Server.
## Публичный запуск

1. Создай проект Supabase на Free и выполни `supabase.sql` в SQL Editor. Он создаст таблицу, правила доступа и хранилище.
2. Заполни `cloud-config.js` значениями Project URL и Publishable key из Connect. Секретный ключ базы в сайт добавлять нельзя.
3. В Cloudflare Workers & Pages создай проект Pages с Direct Upload и загрузи ZIP, в корне которого находится index.html. Выбери свободное имя проекта.
4. В Supabase Auth → URL Configuration добавь адрес сайта, а также точные адреса входа на `index.html` и `category.html` в Redirect URLs. Для публичной регистрации с подтверждением по почте настрой SMTP. Для предварительного теста можно создать учётную запись в Auth → Users и подтвердить её из панели.
5. Проверь публикацию после входа и открытие этой же работы из приватного окна. Проверь скачивание файла и добавление версии.
6. Для переноса IndexedDB временно размести эту же версию сайта на прежнем адресе и разреши там редиректы Supabase. На старом адресе войди в аккаунт и нажми **Account → Publish local ideas**. Кнопка подтверждает публичную загрузку и сохраняет локальные копии. Если ветка не переносится из-за недоступного родителя или отозванного разрешения, она остаётся в браузере.

Для резервной копии нужны и таблица, и файлы из Storage. Экспорт базы не включает сами изображения.
